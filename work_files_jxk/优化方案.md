## 多连接并行传输方案：面向多核的架构设计

### 一、核心设计原则

在用户态传输协议（如 XQUIC）中，吞吐量优化的关键在于**让每个 CPU 核心独立处理一个连接，避免任何跨核的资源竞争**。基于此，提出以下架构原则：

1. **连接与核心绑定**：每个 QUIC 连接独占一个 CPU 核心，实现无锁处理
2. **Engine 与连接 1:1 映射**：每个连接拥有独立的 XQUIC Engine 实例
3. **Event Base 隔离**：每个线程独立的事件循环
4. **上层应用无感**：通过透明代理层封装多连接的复杂性

### 三、组件隔离设计

#### 3.1 XQUIC Engine 隔离

**为什么需要隔离**：XQUIC Engine 维护连接状态机、拥塞控制上下文、定时器等全局资源。多个连接共享一个 Engine 时，内部需要锁保护。XQUIC 的核心优势之一是**拥塞控制算法可以精细到连接粒度**，这正是独立 Engine 的天然基础。

```c
// 隔离架构：每个连接独立 Engine
typedef struct {
    int core_id;                    // 绑定的 CPU 核心
    xquic_engine_t* engine;        // 独立 Engine 实例
    xquic_conn_t* conn;             // 单一连接
    event_base_t* event_base;       // 独立事件循环
    int udp_fd;                     // 独立 UDP socket
} IsolatedConnection;

// 初始化：N 个连接 = N 个独立 Engine
void init_isolated_connections(int num_cores) {
    for (int i = 0; i < num_cores; i++) {
        IsolatedConnection* ic = malloc(sizeof(IsolatedConnection));

        // 1. 创建独立 Engine（关键：不与其它连接共享）
        xquic_engine_config_t eng_cfg = xquic_engine_config_default();
        eng_cfg.core_affinity = i;   // 绑定核心
        ic->engine = xquic_engine_create(&eng_cfg);

        // 2. 创建独立 Event Base
        ic->event_base = event_base_new();

        // 3. 创建独立 UDP socket
        ic->udp_fd = socket(AF_INET, SOCK_DGRAM, 0);

        // 4. 绑定到指定核心
        bind_to_core(ic->udp_fd, i);

        // 5. 在该 Engine 上创建连接
        ic->conn = xquic_conn_create(ic->engine, server_addr, &conn_cfg);

        // 6. 将 fd 注册到 event_base
        event_add(ic->udp_fd, EV_READ, callback, ic);
    }
}
```

**关键点**：

- 每个 Engine 只服务一个连接，内部无需任何锁
- 拥塞控制状态完全私有，无缓存失效开销

#### 3.2 Event Base 隔离

**为什么需要隔离**：QUIC 依赖定时器驱动丢包检测和 PTO 探测。共享 Event Base 会导致定时器冲突和事件处理排队。

```c
// 独立事件循环线程
void* event_loop_thread(void* arg) {
    IsolatedConnection* ic = (IsolatedConnection*)arg;

    // 绑定 CPU 核心
    bind_thread_to_cpu(pthread_self(), ic->core_id);

    // 独立的事件循环
    while (ic->running) {
        // 1. 处理 UDP IO
        event_base_loop(ic->event_base, EVLOOP_ONCE);

        // 2. 驱动 XQUIC 引擎（处理定时器、丢包检测）
        xquic_engine_process(ic->engine);

        // 3. 发送待发数据
        xquic_engine_send_pending(ic->engine);
    }
    return NULL;
}
```

**隔离收益**：

- 定时器精度：每个连接的 PTO 探测独立触发，不受其他连接影响
- 延迟可预测：无事件排队等待

#### 3.3 上层应用无感设计

对应用层透明是关键目标。通过 **Session Layer** 封装多连接的复杂性：

```c
// 应用层接口（与单连接完全相同）
typedef struct {
    void* internal_state;           // 多连接会话状态
    int (*send)(Session* sess, const uint8_t* data, size_t len);
    int (*recv)(Session* sess, uint8_t* buf, size_t len);
    int (*close)(Session* sess);
} Session;

// 内部实现：Round-Robin 分发到各隔离连接
int session_send(Session* sess, const uint8_t* data, size_t len) {
    // 根据 data 偏移量选择目标连接
    int target_core = (atomic_fetch_add(&sess->next_core, 1) % sess->num_cores);
    IsolatedConnection* ic = sess->connections[target_core];

    // 直接调用对应 Engine 的发送接口（无锁）
    return xquic_conn_send(ic->conn, data, len);
}
```

**透明性保证**：

- 上层代码完全无感知，使用 Session 就像使用单连接
- 连接数调整无需修改业务代码

### 四、CPU 资源利用优化

#### 4.1 网卡队列与 CPU 绑定

结合之前的网卡配置（16 Combined 队列），IRQ 亲和性配置与连接隔离形成端到端的无锁路径：

```
网卡 RX Queue 0 → IRQ 绑定 Core 0 → UDP Socket 0 → Engine 0 → Conn 0
网卡 RX Queue 1 → IRQ 绑定 Core 1 → UDP Socket 1 → Engine 1 → Conn 1
...
网卡 RX Queue 15 → IRQ 绑定 Core 15 → UDP Socket 15 → Engine 15 → Conn 15
```

**配置方法**：

```bash
# 1. 设置网卡队列数 = CPU 核心数
ethtool -L enp137s0f5 combined 16

# 2. 配置 IRQ 亲和性（每个队列绑定到对应核心）
./set_irq_affinity.sh enp137s0f5

# 3. SO_REUSEPORT 让多个 socket 绑定同一端口
# 内核将数据包按 4-tuple 哈希分发到不同 socket
```

#### 4.2 零拷贝路径

```c
// 每个隔离连接独立的零拷贝发送
void isolated_send(IsolatedConnection* ic, const uint8_t* data, size_t len) {
    // 直接使用预分配的缓冲区，无锁竞争
    xquic_send_buffer_t* buf = get_free_buffer(ic->core_id);
    memcpy(buf->data, data, len);

    // Engine 直接发送，无跨核调用
    xquic_engine_send(ic->engine, ic->conn, buf);
}
```

### 五、性能预期

| 架构                        | 锁开销   | CPU 缓存 | 吞吐线性度  | 实现复杂度 |
| ------------------------- | ----- | ------ | ------ | ----- |
| 共享 Engine + EventBase     | 高     | 频繁失效   | 差      | 低     |
| **隔离 Engine + EventBase** | **无** | **完美** | **线性** | **中** |

基于阿里 XQUIC 在短视频场景的实践：多连接并行 + 多核绑定实现 **20% 分片下载耗时优化**和 **10% 卡顿率降低**。
